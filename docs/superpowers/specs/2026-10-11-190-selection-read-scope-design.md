## Selected bounded lifetime

Add an internal selection-store read scope owned by one awaited operation.
A scope takes its original actual AbortSignal and exact finite monotonic deadline,
no more than30000milliseconds in the future. It cannot accept an injected clock,
root, account, descriptor, receipt, provider, script or current observation.
The scope itself grants no authority and produces no public capability.

Only calls explicitly carrying that identical signal and exact deadline may
borrow its descriptor. Utilities without that explicit context retain their
existing separate one-shot path. Different contexts cannot borrow or renew it.
Nested scopes in the same store refuse. Separate store instances never share
scope records, guards, pending calls or cleanup obligations.

Each read/admission still initializes its ordinary portable system, freshly
observes the OS account and canonical path components, and executes both fresh
snapshots, existing principal/protection checks, generation comparisons and
full installed inventory checks. Compare each freshly derived account directory
with the scope's initially bound directory before borrowing. A mismatch refuses;
the scope cannot migrate to a new account root or adopt replacement protection.

The first matching read uses the existing observeProtection/openProtectedRoot
path. Retain only that genuine C1 descriptor and its existing original binding.
Later matching reads use the retained guard, which independently verifies the
root, ancestry, token, ACL and exact file generation on every observation.
Never reuse current account, principal, ACL, bytes, source inventory or permission
results. Do not provision or repair a store while borrowing its read scope.
Selection registration/update is outside this read-only scope.

There is one in-flight initialization promise, so concurrent matching reads
cannot open multiple retained descriptors. Track every participating store call,
including calls the callback neglects to await. Queueing and observations consume
the original deadline; no fresh timeout begins on borrowing or dequeue.
A scope closing or poisoned by a failed read refuses further matching calls.
It never reopens a descriptor or retries a failed read in that original scope.

## Completion and uncertain cleanup

The scope runs its callback, then stops new borrowing and establishes quiescence
of tracked reads before closing its particular retained guard. A callback cannot
return success while an unawaited read or descriptor close remains unresolved.
Pending work remains subject to the original deadline. Do not introduce an
unbounded cleanup wait, abort someone else's signal, renew query authority, or
claim that returning from a callback proves child/descriptor exit.

Closing after expiry may release an already owned resource; it cannot authorize
another read or effect. Retain the real guard, pending calls and bounded cleanup
obligation on uncertainty. The scope refuses completion. Existing explicit
cleanup retries may discharge only an actually observed closure; they grant no
new read authority and cannot revive the poisoned scope.

Keep private records of the last genuine selection snapshot and installed
inventory used by successful participating admissions. After the last awaited
closure, synchronously revalidate the protected snapshot, declared installed
source/inventory and original context before returning a result. This closes the
new await boundary introduced by retaining the descriptor across the callback.
No stale callback result, serializable counter or copied observation can pass
that final boundary. Preserve existing later effect fences and source membership.
