# #209 Portable Owner Reconciliation Design

## Intent and authority

Implement the missing C6 prerequisite discovered by #190. Installed review users must be able to start a broker after genuine current source admission for empty stores, clean/idle-stopped stores, and crashes with no registered non-terminal review, without discarding unresolved registry, manual, wake or provider effects. Recovery after an active automatic review crashes is explicitly NOT delivered by #209: retained dead-instance provider/coordinator generations require separately delivered exact recovery producers. The user explicitly approved tracking and completing this repair inline, preserving security checks and original budgets. #209 belongs to #171; #190 resumes after the repair lands. Original #141/#107 obligations remain.

The current observer always returns unknown. The actual guarded refusal control and hosted installed run 38288385677 agree. Checking owner-private `registry.json` and `manual-suspension.json` cannot establish the state of the real registration, review or independent resource stores. A caller's callback or an empty cache is not reconciliation authority.

## Production boundary

Keep `observePortableReconciliation({paths,signal,deadline})` as the fixed production entry. `inspectOwnerElectionPaths` authenticates the opaque owner binding and its original context. Derive the physical worktree from the canonical `.scratch/peer-review/private` root, then independently reproduce its stock portable project identity. An arbitrary private/runtime pair cannot identify a production project. Original owner records and their quarantine remain C4-owned.

The observer returns a frozen observation with `status`, bounded obligations and an opaque private record. A clear result is operationally usable only through private membership, exact owner binding, project identity and original context. Add `assertPortableReconciliation({observation,paths,signal,deadline})`; it freshly reobserves every retained directory membership and relevant file generation before returning. Copied results, changed context, deadline expiry and cleanup uncertainty refuse. Pure classifier results and fixture ports remain `verified:false` and cannot pass that assertion.

Owner preparation retains the genuine observation privately and asserts it immediately before each quarantine and creation effect. Publication asserts again immediately before `publishEndpoint` (the first discoverable effect) and immediately before `lifecycle.publish`, using the restoration contract below. The protocol core remains independently testable and unverified; its clear fixture result cannot become a production capability.

The owner's fixed input keys become `deadline,paths,protection,signal,worktree`, optionally plus legacy `reconcile`. Both shapes are accepted; other keys refuse. A supplied legacy key is ignored and never invoked. The service omits it. No callback, receipt-shaped object or caller flag replaces the fixed observer.

ENOENT alone is not a reconciliation result.

## State classification and restoration

Use existing closed schemas and exact authority readers, not permissive JSON flags. Empty, exact terminal/preserved, durably manually fenced and legitimately restorable dispositions produce `status: clear` with zero public outstanding obligations. Every other disposition produces non-clear status plus bounded obligations. A restorable entry is NOT an unresolved obligation: its exact registration/workspace/retained generations are carried exclusively in the private observation record.

A pre-launch restorable registration has exact request/event/output/runtime authority, complete manual non-submission coverage, no unresolved wake/provider operation and no retained independent resource blocker. The fixed production observer obtains the exact registration set using the existing production registry/history authority, including preserved history; callers cannot supply preservation flags. For an acknowledged launched review, the read-only matching predicate is exactly journal.stage === launched, provider_operation.status === acknowledged, and provider_operation.session_fingerprint === the current sealed reviewer session_fingerprint, with the existing closed intent/request checks. This is the acknowledged branch of joinedLaunchMatches; its reserved/unknown branches do not prove acknowledgement. Matching acknowledged reviews are restorable unless a separate retained resource or coordinator obligation blocks them.

Reserved, unknown or contradictory launch/wake effects remain unresolved. Original broker death does not prove provider/manual completion. An acknowledged provider effect may be retained only when existing exact-session reconciliation proves its current restoration route; otherwise refuse. This repair does not create a new provider completion/discharge rule.

Retained provider-resource records for this project remain blockers unless the existing live producer establishes the exact permitted disposition. A record left by a different/non-live broker instance is a terminal operator obligation named `provider-resource-retained`: the current tree has no explicit orphan-discharge route. [Follow-up #210](https://github.com/kburson/ai-peer-review/issues/210) owns that missing operation; it is not a dependency of #209's narrowed empty/clean startup capability, but it IS a dependency of active-review crash recovery. It is never an automatic clearance waiver. Never unlink or reclaim a retained record based on broker death, age or endpoint silence. A settled manual resource is nonblocking only when its exact durable fence digest, review/request identity and exclusion generation are proved AND the original settlement producer's genuine C1 protection on the review workspace is still verified. Ordinary 0755 review workspaces cannot prove that settlement and remain blockers; no ordinary fence hash substitutes for the protected producer. the record remains intact. Pending suspension, unmatched settlement and retained election uncertainty refuse.

The observer itself performs no writes. A separate fixed pre-creation reconciliation step may invoke only the existing exact launch/wake reconciliation producers under the genuine held election and current #102 effect authority. It may append their proved outcomes, but may never reserve or submit a new launch/wake, retire a provider resource, or perform manual fencing. Those effects remain with their independently elected producers. Partial observations preserve bounded exact obligations and cannot produce clear. #190's positive crash/reclaim controls use a broker with no registered non-terminal review and no held provider/coordinator resource. An active automatic-wait review crash must produce an exact retained provider/coordinator refusal, not a recovery claim. Crashing with a held provider resource must demonstrate the bounded refusal and retained generation; it is not positive reclaim evidence.

## Bounded pre-creation recovery

`preparePortableReconciliation({paths,lease,signal,deadline})` requires the actual won owner-election lease, its bound paths/source and original context. It first observes complete stores. When a valid interrupted launch or reserved wake has an existing exact reconciliation producer and no independent retained-resource blocker, `reconcilePortableExistingEffects` invokes that producer before any owner/credential/quarantine creation. The fixed new `src/broker/portable-existing-effect-reconciliation.mjs` constructs the sealed participant adapter/binding directly from the exact startup descriptor, current participant record and existing binding validators. Extract the common read-only adapter/binding selection from worker-factory-core into `src/broker/portable-participant-binding.mjs`; both the ordinary worker and this producer use it. Neither module creates a worker or acquires/writes a provider-resource lease. Callers cannot inject a probe, owner, adapter, acceptance flag or successful outcome.

In this pre-creation path, the production authorization replaces owner.verify with inspectOwnerElectionLease/lease.assert on the exact won lease plus revalidateInstalledProcessSourceAssurance under the original signal/deadline, and fresh current #102 authority at each outcome write. The permit is privately issued and bound to paths, source, project and election. A copied lease, source receipt or participant binding refuses. Add a production-used control requiring unchanged provider-resource membership through pre-creation reconciliation and refusal without a genuine won lease.

Launch-pending/outcome-unknown entries use the existing exact-session `reconcileReviewerLaunch` producer. Reserved wake entries use an extracted reconciliation-only form of `reconcileReserved`: inspect existing operation and invoke the exact existing adapter reconciliation, append only its proved outcome, then stop. It must not call reserveWakeOperation, deliverReserved, startCoordinator or launchReviewer. Unknown/unavailable/mismatched outcomes remain non-clear. All writes cross fresh current #102 effect checks and the genuine held election; reobserve the resulting exact generations before issuing the ordinary observation seal.

`peer-review broker reconcile <workspace>` uses this same fixed bounded pre-creation route when no broker is live, through ensureBroker, only if no retained independent resource or coordinator generation blocks admission. A crash-interrupted launch/wake that has dead-instance provider/coordinator records reports the terminal retained-generation operator obligations instead; it cannot reach this route until those prerequisites are resolved. Thus it can reach exact reconciliation without first granting ownership to unresolved effects. If the required probe is unavailable, it returns `existing-effect-reconciliation-unproved` with an exact retained obligation and instructions to preserve that operation and restore its official observation capability. Repeating startup is not reported as recovery. Independent orphan provider records remain the separately tracked #210 operator case.

## Restoration and publication generations

`readPreparedPortableRegistrations({owner,signal,deadline})` obtains the privately classified exact startup set after a fresh assertion. Service startup uses that set, never an independent registry enumeration. A new or changed registration before/during restoration refuses. After startup, existing current-authority registration commands remain the route for later reviews; the initial set is not a permanent registry cache.

The production worker facade in `worker-factory.mjs` gains private membership and startup restoration state. Factory creation (including provider acquisition and releaseUnused unwind) and successfully completed, current-authority-wrapped start/suspend/close transitions issue the applicable private restoration receipts. Failed/uncertain unwind retains obligations rather than granting a receipt. The receipt binds the actual prepared owner, registration, original startup context, before/after authority-bearing generations, broker/recovery records and any genuine provider lease acquired by that worker. Copied workers, arbitrary counters, callback results and caller-supplied generations never qualify. A recovery-only worker retains its genuine settled receipt after suspension/close even after removal from the live worker map.

`acceptPortableWorkerRestoration({owner,receipt,signal,deadline})` checks private worker-receipt membership, exact initial registration and prior workspace generation, then retains the producer-issued current generation privately. It does not ignore a changed workspace or merely refresh the baseline. An unexpected write outside the authorized worker transition, an unknown resulting provider/wake/manual disposition or an unbound provider lease refuses.

Before `publishEndpoint` and `lifecycle.publish`, require unchanged project registration/review membership, exact unchanged non-restored generations, and freshly validated relevant account associations. For restored entries, compare against the genuine worker-issued generation rather than the pre-restoration snapshot. Newly acquired current-owner provider resources are allowed only when bound to the genuine worker's still-held production resource lease, freshly asserted; they are retained, never discharged. Pending/foreign/changed resources and independent concurrent manual changes remain unresolved. Restoration receipts therefore authorize only those closed, actual producer transitions, not arbitrary store churn.

Production factory selects restoration mode from genuine prepared-owner membership; it is not a caller acceptance flag. In this mode worker.start observes/classifies and settles only bounded restoration work. It defers startCoordinator and all new reviewer launch/provider wake until lifecycle.publish has succeeded. Service defers onStateChange-driven asynchronous settlement during startup and explicitly awaits the initial settlement sequence. There must be no unreceipted background mutation between final restoration checks and publication.

After publication, the service activates the genuine restored workers under the published owner's existing lifecycle authority, using their normal independent dispatched-operation contexts. This is not renewal of the startup deadline: activation cannot retroactively rescue an expired startup. A copied/unpublished owner or failed publication cannot activate coordination or delivery. Add an automatic-wait control whose coordinator would reserve a wake: endpoint/lifecycle publication must occur first and the pre-publication wake counter must stay zero.

Service must collect receipts after factory creation and every startup worker transition, including recovery-only suspension/close, before publication. Add a real production-used restoration harness proving publication with a restorable registration and recovery-only suspension; separately reject a new registration, external manual mutation, changed receipt generation or fabricated worker during the same window.

## Original context and concurrency

Startup keeps the sealed absolute monotonic deadline, at most 30000 ms, and original AbortSignal. Every nested stock operation uses those exact values. No new clock, timeout renewal, freshness TTL or admission cache. Normal recovery and cleanup use their existing separately issued lifecycle contexts; a startup observation cannot authorize them.

Hold the genuine broker election while observing and deciding. Independently protected manual/provider elections are not nested broker locks and are not retired. Relevant same-project or ambiguous concurrent changes invalidate the observation unless covered by the exact genuine restoration transition above; validated foreign churn is freshly reclassified. Restoration and final publication reobserve relevant review/resource state and respect durable manual exclusion. C4 continues to independently prove original-process death, authenticate conflicting endpoints and preserve owner/quarantine generations.
