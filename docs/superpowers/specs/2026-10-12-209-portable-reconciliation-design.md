# #209 Portable Owner Reconciliation Design

## Intent and authority

Implement the missing C6 prerequisite discovered by #190. Installed review users must be able to start or recover a broker after genuine current source admission, without discarding unresolved registry, manual, wake or provider effects. The user explicitly approved tracking and completing this repair inline, preserving security checks and original budgets. #209 belongs to #171; #190 resumes after the repair lands. Original #141/#107 obligations remain.

The current observer always returns unknown. The actual guarded refusal control and hosted installed run 38288385677 agree. Checking owner-private `registry.json` and `manual-suspension.json` cannot establish the state of the real registration, review or independent resource stores. A caller's callback or an empty cache is not reconciliation authority.

## Production boundary

Keep `observePortableReconciliation({paths,signal,deadline})` as the fixed production entry. `inspectOwnerElectionPaths` authenticates the opaque owner binding and its original context. Derive the physical worktree from the canonical `.scratch/peer-review/private` root, then independently reproduce its stock portable project identity. An arbitrary private/runtime pair cannot identify a production project. Original owner records and their quarantine remain C4-owned.

The observer returns a frozen observation with `status`, bounded obligations and an opaque private record. A clear result is operationally usable only through private membership, exact owner binding, project identity and original context. Add `assertPortableReconciliation({observation,paths,signal,deadline})`; it freshly reobserves every retained directory membership and relevant file generation before returning. Copied results, changed context, deadline expiry and cleanup uncertainty refuse. Pure classifier results and fixture ports remain `verified:false` and cannot pass that assertion.

Owner preparation retains the genuine observation privately and asserts it immediately before each quarantine and creation effect. Publication asserts again immediately before `publishEndpoint` (the first discoverable effect) and immediately before `lifecycle.publish`, using the restoration contract below. The protocol core remains independently testable and unverified; its clear fixture result cannot become a production capability.

The owner's fixed input keys become `deadline,paths,protection,signal,worktree`, optionally plus legacy `reconcile`. Both shapes are accepted; other keys refuse. A supplied legacy key is ignored and never invoked. The service omits it. No callback, receipt-shaped object or caller flag replaces the fixed observer.

Ordinary observation is a read-only physical integrity mechanism, not a C1 capability and not a substitute for #102 current authority or private owner protection. It checks canonical contained non-link directory chains and retains real directory handles/metadata around enumeration and ordinary file reads. Relevant bytes and file/root/parent identities must agree before and after the existing authority parser runs. An unreadable, aliased, linked, malformed or changing observation refuses. Never replace a retained generation silently.

Add `listOrdinaryEntries()` only to genuine C1 guards for their actual protected namespaces. It verifies current principal/protection/root/parent identity before and after enumeration, rejects links/reparse points and unsupported types, bounds count and names, and returns closed ordinary names/types. It grants no write, election or source authority. For ordinary namespaces, implement the separate retained physical-directory enumeration in `portable-reconciliation-inventory.mjs`; never mint a protected-root receipt from it.

Complete discovery covers registrations AND all direct/nested review transactions, including orphans; exact per-review wake/manual/provider authority; and complete account manual/provider resource stores. It does not depend exclusively on known registration IDs or resource descriptors. Missing paths are observed beneath the nearest retained physical parent and rechecked at effects. Where that parent is genuinely protected, retain its C1 checks; elsewhere apply the ordinary chain/membership checks described above and state their weaker protection honestly. ENOENT alone is not a reconciliation result.

Bound the whole observation to 4096 entries, depth 16 and 1048576 bytes per authority-bearing ordinary file. The same original deadline covers every enumeration, parser and per-root stock protection query, including subprocesses; there is no per-root renewal. Refuse count/depth/byte overflow as `reconciliation-inventory-overflow`, deadline exhaustion as `reconciliation-deadline`, and abort as `reconciliation-aborted`. Close failures retain exact descriptor obligations and cannot report clear. These bounds are limits, not forecasts that all admissible counts fit in 30 seconds.

The direct project scratch reserved directories are exactly `private`, `runtime`, `runtimes`, `broker` and `reviews`. Review transaction names must use the existing closed review-ID grammar and must validate their own canonical workspace/request identity. Unknown root entries or unknown authority-bearing child names refuse with `reconciliation-namespace-unproved`; inert payload/response text is not parsed as an effect grant.

A directory with no startup journal AND no events is not silently dropped. A wholly empty/incompletely initialized review directory is an unresolved `review-initialization-unproved` obligation; no automatic deletion or inferred non-submission is allowed. A reserved journal without events is classified under the existing startup-transaction rules only after complete inventory shows no wake, provider, manual-launch or independent resource obligation. Add controls for empty/uninitialized, interrupted reserved and malformed transactions. Manual inspection/preservation is required for an unattributed empty directory; missing cache is never external-effect proof.

Validate unrelated project associations before excluding account resources. Changes/additions to global account membership trigger fresh association classification: any new or changed same-project or ambiguous record refuses unless covered by a genuine current restoration receipt. A previously known foreign entry is revalidated and may remain foreign without invalidating this project's startup. This is bounded fresh observation within the original deadline, not an automatic retry with a renewed budget.

No private bytes, credentials or nonce digests enter diagnostics or tracked evidence. Snapshot and classifier data cannot mint operational membership.

## State classification and restoration

Use existing closed schemas and exact authority readers, not permissive JSON flags. Empty, exact terminal/preserved, durably manually fenced and legitimately restorable dispositions produce `status: clear` with zero public outstanding obligations. Every other disposition produces non-clear status plus bounded obligations. A restorable entry is NOT an unresolved obligation: its exact registration/workspace/retained generations are carried exclusively in the private observation record.

A pre-launch restorable registration has exact request/event/output/runtime authority, complete manual non-submission coverage, no unresolved wake/provider operation and no retained independent resource blocker. The fixed production observer obtains the exact registration set using the existing production registry/history authority, including preserved history; callers cannot supply preservation flags. Acknowledged active provider effects lacking a proved restoration route remain unresolved.

Reserved, unknown or contradictory launch/wake effects remain unresolved. Original broker death does not prove provider/manual completion. An acknowledged provider effect may be retained only when existing exact-session reconciliation proves its current restoration route; otherwise refuse. This repair does not create a new provider completion/discharge rule.

Retained provider-resource records for this project remain blockers unless the existing live producer establishes the exact permitted disposition. A record left by a different/non-live broker instance is a terminal operator obligation named `provider-resource-retained`: the current tree has no explicit orphan-discharge route. [Follow-up #210](https://github.com/kburson/ai-peer-review/issues/210) owns that missing operation; it is not a dependency or automatic clearance waiver for #209. Never unlink or reclaim a retained record based on broker death, age or endpoint silence. A settled manual resource is nonblocking only when its exact durable fence digest, review/request identity and exclusion generation are proved; the record remains intact. Pending suspension, unmatched settlement and retained election uncertainty refuse.

The observer performs no reconciliation writes, launch, wake, provider retirement or manual fencing. Those effects remain with existing authenticated and independently elected producers. Partial observations preserve bounded exact obligations and cannot produce clear. #190's positive crash/reclaim controls must crash at a point with no held provider resource. Crashing with a held provider resource must demonstrate the bounded refusal and retained generation; it is not positive reclaim evidence.

## Restoration and publication generations

`readPreparedPortableRegistrations({owner,signal,deadline})` obtains the privately classified exact startup set after a fresh assertion. Service startup uses that set, never an independent registry enumeration. A new or changed registration before/during restoration refuses. After startup, existing current-authority registration commands remain the route for later reviews; the initial set is not a permanent registry cache.

The production worker facade in `worker-factory.mjs` gains private membership and startup restoration state. Only a successfully completed, current-authority-wrapped `start`/`suspend`/`close` transition can issue a restoration receipt. The receipt binds the actual prepared owner, registration, original startup context, before/after review generations, and any genuine provider lease acquired by that worker. Copied workers, arbitrary counters, callback results and caller-supplied generations never qualify. A recovery-only worker retains its genuine settled receipt after suspension/close even after removal from the live worker map.

`acceptPortableWorkerRestoration({owner,receipt,signal,deadline})` checks private worker-receipt membership, exact initial registration and prior workspace generation, then retains the producer-issued current generation privately. It does not ignore a changed workspace or merely refresh the baseline. An unexpected write outside the authorized worker transition, an unknown resulting provider/wake/manual disposition or an unbound provider lease refuses.

Before `publishEndpoint` and `lifecycle.publish`, require unchanged project registration/review membership, exact unchanged non-restored generations, and freshly validated relevant account associations. For restored entries, compare against the genuine worker-issued generation rather than the pre-restoration snapshot. Newly acquired current-owner provider resources are allowed only when bound to the genuine worker's still-held production resource lease, freshly asserted; they are retained, never discharged. Pending/foreign/changed resources and independent concurrent manual changes remain unresolved. Restoration receipts therefore authorize only those closed, actual producer transitions, not arbitrary store churn.

Service must collect receipts after every startup worker transition, including recovery-only suspension/close, before publication. Add a real production-used restoration harness proving publication with a restorable registration and recovery-only suspension; separately reject a new registration, external manual mutation, changed receipt generation or fabricated worker during the same window.

## Original context and concurrency

Startup keeps the sealed absolute monotonic deadline, at most 30000 ms, and original AbortSignal. Every nested stock operation uses those exact values. No new clock, timeout renewal, freshness TTL or admission cache. Normal recovery and cleanup use their existing separately issued lifecycle contexts; a startup observation cannot authorize them.

Hold the genuine broker election while observing and deciding. Independently protected manual/provider elections are not nested broker locks and are not retired. Relevant same-project or ambiguous concurrent changes invalidate the observation unless covered by the exact genuine restoration transition above; validated foreign churn is freshly reclassified. Restoration and final publication reobserve relevant review/resource state and respect durable manual exclusion. C4 continues to independently prove original-process death, authenticate conflicting endpoints and preserve owner/quarantine generations.
